# 服装集团业务系统功能全景 V1.0

> 文档级别：立项 / 系统选型 / PRD / 开发拆解母版
> 冻结日期：2026-09
> 说明：本版“SaaS”理解为成熟商业软件/专业套件，实际部署可以是 SaaS、私有化或本地部署，并不限定公有云。

## 1. 建设归属定义

| 标记 | 定义 | 典型系统 |
|---|---|---|
| ERP | 标准交易、财务、成本、采购等成熟能力 | ERP、财务、采购 |
| SaaS | 专业领域优先采购成熟产品，不重复造轮子 | PLM、SRM、WMS、MES、POS、CRM |
| 自研 | 直接形成服装企业竞争优势、规则变化频繁 | 商品企划、配货、补货、调拨、商品运营 |
| 集团中台 | 多品牌、多法人、多渠道必须共享的基础能力 | 商品、库存、订单、会员、MDM、数据、集成 |

## 13. 功能规模汇总

- **48 个一级业务模块**
- **252 个二级业务模块**
- 详细设计后预计 800～1500 个三级功能点
- 典型三级功能：页面、按钮/操作、工作流、状态机、权限、API、系统事件、消息通知、数据规则、算法规则、数据报表、系统配置

## 14–16. 四类建设方式总体分工

- **ERP 负责**：已经确定并发生的业务交易（采购、生产订单、MRP、成本、应收、应付、总账、资金、税务、集团财务）。不让 ERP 承担全渠道实时库存、商品运营和消费者运营。
- **SaaS/商业系统负责**：PLM、SRM、APS、MES、QMS、WMS、TMS、RFID、POS、DMS、CRM、CDP、HR、OA/BPM。集团重点做系统选型 + 流程配置 + 接口标准 + 数据治理。
- **重点自研**：
  - 商品数字运营平台：商品企划、商品结构、波段、价格带、SKU 规划、商品生命周期、商品分析
  - 智能商品运营平台：配货、补货、调拨、售罄、库销比、滞销分析、补单建议、清仓建议
  - 渠道商品中心：PIM、DAM、商品素材、商品模板、渠道商品、商品转换、商品发布（集团商品 → PIM → DAM → 渠道商品生成 → 抖音/天猫/京东/拼多多）

## 17. 集团中台 12 个核心中心

01 商品中心（SPU/SKU/款号/颜色/尺码/条码）
02 PIM 商品信息中心（标题/卖点/详情/属性/渠道商品数据）
03 DAM 素材中心（图片/视频/PSD/设计源文件/详情页素材）
04 库存中心 IMS（库存/ATP/锁定/预占/渠道分配）
05 订单中心 OMS（订单/拆单/合单/履约/路由）
06 价格中心（零售价/吊牌价/会员价/地区价格/渠道价格）
07 促销中心（优惠券/折扣/满减/活动规则）
08 会员中心（One ID/等级/积分/权益）
09 结算中心（平台/供应商/加盟商/门店/物流结算）
10 主数据中心 MDM（统一编码与数据标准）
11 数据平台（ODS/DWH/BI/指标/AI）
12 集成平台（API/事件/消息/系统互联）

## 18. 最终集团系统目标架构

```
集团经营层（BI/指标/AI决策） → 数据平台（ODS/DWH/Lakehouse） → 集团数字中台（商品/PIM/DAM/库存/订单/价格/促销/会员/结算/MDM）
→ PLM/SRM/QMS | ERP/APS/MES/工厂 | WMS/TMS/RFID | OMS/POS/电商平台/门店 | CRM/CDP/营销 | DMS/加盟商
→ API / Event Bus
```

## 19. 建设优先级（不建议同时启动 48 个模块）

- **Phase 0 数字基础**：MDM、集成平台、商品中心、订单中心、库存中心；打通 ERP/PLM/WMS/POS（地基）。
- **Phase 1 商品供应链数字化**：商品企划、PLM、SRM、采购、WMS、商品中心、PIM、DAM。
- **Phase 2 全渠道**：OMS、IMS、POS、电商连接器、售后、会员、结算。
- **Phase 3 商品运营**：配货、补货、调拨、商品生命周期、库存健康度、售罄、商品运营分析（核心竞争力层）。
- **Phase 4 数据和 AI**：集团数据 → 指标中心 → 预测模型 → AI Agent → 经营建议（补货、缺码、调拨、降价、返单、供应商交期风险、下一波段产量、门店 SKU 结构）。

## 20. 后续 PRD 拆解标准

- 一个二级模块 = 一个 Epic（如 26.03 尺码结构模型）
- Epic → Feature（如 门店历史尺码销量 / 商品尺码曲线 / 城市尺码特征 / 门店尺码模型 / 新店尺码继承 / AI尺码预测 / 人工调整 / 模型版本 / 配货调用 / 效果评估）
- Feature → Story → 页面 → 接口 → 数据表 → 状态机 → 权限 → 测试用例

本 48×252 功能全景可直接作为后续 PRD、原型、数据库设计、API 设计和研发任务树的顶层骨架。
