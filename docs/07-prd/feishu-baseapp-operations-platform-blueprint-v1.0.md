## 1. 决策与定位

飞书定位为：

> 第一阶段完整可用的业务运营平台与 PoC，同时作为后续自研核心系统的前台和协同层。

飞书承载入口、表单、流程、审批、看板、协同记录、异常闭环与核心数据投影。Product Master、OMS、IMS、领猫、聚水潭及集成平台继续承担永久主键、强唯一约束、交易一致性、事件、审计和外部执行事实。

这一定位不改变已有治理原则：一个业务事实只能有一个最终写入权威；飞书中的投影、汇总和反向关联不获得该事实的所有权。

### 4.1 前后台分离

- 普通用户只进入 BaseApp，不直接面对 25 张原始表。
- Base 原始表、字段和自动化仅向系统管理员、数据管理员和受授权的业务管理员开放。
- 供应商不进入内部 Base；通过表单或专属页面提交数据。
- 管理层默认进入经营总览，只在异常或指标下钻时看到记录明细。
- Agent 默认只读，写入必须走受控动作、Workflow 或审批。

### 5.1 页面设计规则

1. 每个岗位首页最多呈现 5 个高频动作和 8 个关键指标。
2. 列表默认只展示 6–10 个岗位必要字段，完整字段放详情抽屉。
3. 创建、更新、审批和关闭使用明确按钮；不让普通用户直接编辑整行。
4. 每个页面必须提供状态、负责人、时限和异常入口。
5. 把表格视图作为数据组件嵌入页面，不把原始表名直接当一级导航。
6. 移动端优先页面：供应商上报、QC 日报、回货登记、异常上报。
7. 管理层页面只展示汇总和异常，下钻后仍受记录级权限控制。

### 6.1 权限落地规则

- **页面权限**：按角色隐藏无关页面，避免“所有人看到所有表”。
- **记录权限**：跟单、QC、采购默认只看本人负责或本人协作记录；管理层可看全局。
- **字段权限**：成本、付款、联系方式、员工手机号、外部系统 ID、审计字段单独控制。
- **供应商隔离**：外部供应商只使用表单或专属页面，不获得 Base 数据后台访问权。
- **身份字段**：`spu_id/sku_id/color_id/size_id/variant_key` 仅由 Product Master 流程写入。
- **交易字段**：订单、库存、物流、售后执行事实由聚水潭/OMS/IMS/WMS 同步；飞书侧默认只读。
- **管理员边界**：系统管理员能配置结构，不默认拥有修改业务事实的权限；应急修改必须留原因和审计记录。

处置类型：

- **保留**：结构与边界基本符合第一期使用。
- **保留并调整**：不删表、不清数据，后续补主键、权限、字段归属或页面表达。

- **采集暂存表**：用于外部填报，验证后再转入正式业务对象。
