## 5. 权限现状与上线 Gate

Base 已启用高级权限，当前保留 11 个既有角色。8 个业务自定义角色已经覆盖经营管理、商品企划、设计研发、采购供应链、生产跟单、QC、仓库和客服售后。

本次没有修改既有角色，因为角色成员映射尚未冻结。实施前盘点发现：

员工花名册现有 13 人，角色字段可识别为：管理层 2、商品企划 2、设计师 2、面辅料采购 1、生产跟单 3、QC 质检 2、QC/跟单兼岗 1。当前花名册尚未覆盖仓库、销售渠道、客服售后、数据分析和系统管理人员，因此不能直接作为完整权限分配依据。

- “01-经营管理层”对 25 张表均为只读。
- 02–08 业务角色已经按职责配置部分可写表。
- “普通用户”当前对 25 张表均可写，并允许复制和下载；这是正式推广前必须收敛的既有风险。
- `Editor`、`Reader` 是系统角色，继续保留。
- 销售渠道、数据分析、系统数据管理和 Codex Agent 的正式角色尚未创建。

在成员清单、部门归属和管理员保底账号确认前，不应直接收紧“普通用户”，避免误伤现有使用者或造成管理员锁定。下一 Gate 是先冻结“人员/部门 → 角色”映射，再以独立变更执行角色创建、成员分配和普通用户权限收敛。

## 6. 当前能力边界

固定版 `lark-cli 1.0.94` 已支持 Workspace、BaseApp、顶级 Page、文本/列表/图表组件和 Base 高级权限角色。本版本暂不支持：

- 创建 PageGroup 或把页面移入页面组。
- 通过 CLI 调整 BaseApp 组件位置和尺寸。
- 通过 CLI 删除 BaseApp 组件。
- 通过 CLI 配置 BaseApp 页面级角色可见性。

因此本阶段使用编号页面实现分区和稳定排序。页面组、布局微调和页面级显示策略需要在飞书 UI 中完成；底层数据权限仍以 Base 高级权限角色为最终控制边界。
